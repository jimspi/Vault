# Auto-Intelligence System

The Auto-Intelligence system is an autonomous recommendation engine that runs automatically on a schedule to generate personalized recommendations for users based on their recent activity.

## Features

### 1. Automated Recommendation Generation
- **Schedule**: Runs 3 times daily at 8am, 2pm, and 8pm in the user's timezone (MST)
- **Activity Detection**: Only generates recommendations if user has recent activity (documents or insights in last 7 days)
- **AI-Powered**: Uses Claude AI to analyze documents, insights, and user profile to create relevant recommendations

### 2. In-App Notifications
- **Notification Bell**: Shows in the navigation bar with unread count badge
- **Real-time Updates**: Polls for new notifications every minute
- **Rich Notifications**: Includes title, message, links, and action buttons
- **Mark as Read**: Notifications can be marked as read or deleted
- **Categorized**: Different notification types with appropriate icons (recommendations, insights, etc.)

### 3. Email Notifications
- **Beautiful HTML Emails**: Professionally designed email templates
- **Actionable**: Direct links to view new recommendations
- **Configurable**: Users can enable/disable email notifications in settings

## Architecture

### Database Tables

#### `notifications`
Stores in-app notifications for users.

```sql
- id: UUID (primary key)
- user_id: UUID (references auth.users)
- workspace_id: UUID (references workspaces)
- type: TEXT (recommendation, insight, etc.)
- title: TEXT
- message: TEXT
- link: TEXT (URL to related content)
- action_text: TEXT (button text)
- related_id: UUID (optional reference to related entity)
- read: BOOLEAN
- read_at: TIMESTAMP
- metadata: JSONB
- created_at: TIMESTAMP
```

#### `user_settings`
Stores user preferences for auto-intelligence features.

```sql
- id: UUID (primary key)
- user_id: UUID (references auth.users, unique)
- timezone: TEXT (default: 'America/Denver')
- email_notifications: BOOLEAN (default: true)
- in_app_notifications: BOOLEAN (default: true)
- auto_recommendations_enabled: BOOLEAN (default: true)
- last_auto_recommendation_at: TIMESTAMP
- metadata: JSONB
- created_at: TIMESTAMP
```

### API Endpoints

#### CRON Endpoint: `/api/cron/auto-recommendations`
**Schedule**: `0 3,15,21 * * *` (8am, 2pm, 8pm MST / 3am, 3pm, 9pm UTC)

**Authentication**: Requires `Authorization: Bearer ${CRON_SECRET}` header

**Process**:
1. Fetch all users with `auto_recommendations_enabled: true`
2. For each user:
   - Find their workspace
   - Check for recent activity (last 7 days)
   - Skip if no recent documents or insights
   - Generate recommendations via internal API call
   - Create in-app notification
   - Send email notification
   - Update `last_auto_recommendation_at` timestamp
3. Return summary of results (success/skipped/errors)

#### Recommendations Generation: `/api/recommendations/generate`
**Method**: POST

**Authentication**:
- User authentication (via session)
- OR Service role (via `Authorization: Bearer ${CRON_SECRET}`)

**Request Body**:
```json
{
  "workspaceId": "uuid",
  "userId": "uuid",          // Required for service role calls
  "isAutoGenerated": true    // Optional flag
}
```

**Response**:
```json
{
  "success": true,
  "recommendations": [...],
  "count": 3
}
```

#### Notifications API: `/api/notifications`
**GET**: Fetch user's notifications
- Query params: `?unreadOnly=true` to filter
- Returns: `{ notifications: [...], unreadCount: 5 }`

#### Notification Management: `/api/notifications/[id]`
**PATCH**: Mark notification as read
**DELETE**: Delete notification

#### Email Notification: `/api/notifications/email`
**POST**: Send recommendation email
**Authentication**: Service role only (`Authorization: Bearer ${CRON_SECRET}`)

**Request Body**:
```json
{
  "to": "user@example.com",
  "recommendationCount": 3,
  "userName": "John Doe"  // Optional
}
```

#### `NotificationBell`
Location: Top navigation bar

Features:
- Bell icon with unread count badge
- Opens popover dropdown on click
- Auto-refreshes count every minute
- Red badge shows count (9+ for 10 or more)

#### `NotificationsPanel`
Location: Popover dropdown from bell

Features:
- Scrollable list of notifications
- Time-based formatting ("2h ago", "3d ago")
- Click to mark as read and navigate to link
- Delete button for each notification
- Empty state when no notifications

### CRON Configuration

**File**: `vercel.json`

```json
{
  "crons": [
    {
      "path": "/api/cron/auto-recommendations",
      "schedule": "0 3,15,21 * * *"
    }
  ]
}
```

**Environment Variables Required**:
- `CRON_SECRET`: Secret key for authenticating CRON requests
- `RESEND_API_KEY`: API key for Resend email service
- `NEXT_PUBLIC_APP_URL`: Full URL of the application (for links in emails)

## User Flow

### Initial Setup
1. User signs up for Vault
2. Default settings created with `auto_recommendations_enabled: true`
3. User uploads documents and creates insights

### Automated Generation
1. CRON job runs at scheduled time (8am, 2pm, 8pm MST)
2. System checks if user has recent activity (last 7 days)
3. If yes, AI analyzes all content and generates 3-5 recommendations
4. Each recommendation includes:
   - Title and description
   - Category (networking, learning, productivity, etc.)
   - Priority level (low, medium, high, urgent)
   - Specific action items with timeframes
   - Real resources (links, tools, articles, events)
   - Reasoning based on user's profile

### Notification
1. In-app notification created with link to recommendations page
2. Email sent with summary and CTA button
3. Notification bell shows unread count
4. User clicks bell to see notification
5. User clicks notification to view recommendations
6. Notification marked as read

### User Actions
- View all notifications in dropdown
- Click notification to navigate to content
- Delete notifications individually
- Mark as read by clicking
- Adjust settings to disable auto-recommendations or email notifications

## Security

- **Authentication**: All endpoints require proper authentication
- **Authorization**: Row Level Security (RLS) ensures users only see their own data
- **Service Role**: CRON jobs use service authentication, not user credentials
- **Secrets**: Sensitive keys stored in environment variables, never in code
- **Input Validation**: All inputs validated before processing

## Performance

- **Efficient Queries**: Database indexes on frequently queried fields
- **Caching**: Profile cache reduces redundant AI generation
- **Pagination**: Notifications panel handles large lists efficiently
- **Async Processing**: CRON job processes users sequentially to avoid rate limits
- **Timeouts**: Long-running operations have appropriate timeout limits

## Troubleshooting

### CRON not running
- Verify CRON is enabled in Vercel dashboard
- Check `CRON_SECRET` environment variable is set
- Review deployment logs for errors

### No notifications appearing
- Check `user_settings` table exists
- Verify `auto_recommendations_enabled: true` for the user
- Ensure user has recent activity (last 7 days)
- Check API logs for errors

### Emails not sending
- Verify `RESEND_API_KEY` is correct
- Check Resend dashboard for delivery status
- Ensure "from" email domain is verified in Resend

### Type errors
- Run `npm run type-check` to identify issues
- Ensure all dependencies installed: `npm install`
